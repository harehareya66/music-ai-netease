直接用浏览器打开 HTML 就能看（`file://` 即可），改完 CSS 重新截图：

```powershell
# 在 music-plugin 目录下
$edge = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
$root = (Get-Location).Path
& $edge --headless=new --disable-gpu --hide-scrollbars `
  --user-data-dir="$env:TEMP\ncm-edge-profile-doc" --window-size=1600,900 `
  --screenshot="$root\design\shots\player.png" "file:///$($root -replace '\\','/')/design/mockups/player.html"
```

要点：
- `--user-data-dir` 放 `%TEMP%`，**不要建在仓库里**（早期用的 `design/.edge-profile` 会污染 git 状态，已废弃）。
- 窗口尺寸按屏给：`player`/`taste`/`lyric` = `1600,900`；`weekly` = `1600,960`（国内周报分享图比例）；`scene` = `1600,930`。
- 每次改 CSS 必须重截对应屏，`shots/*.png` 与 mockup 必须同源。

### 数据可视化用色（本版新增，所有图表必须遵守）

| 场景 | 颜色 |
|---|---|
| 图表类别（环形图分块、柱、条） | **中性灰阶**：`#E8EAED → #8B909A → #5A6070 → #3A3F4A`，按序取 |
| 当前 / 选中 / 峰值 / 第一名 | `--red` `#E5484D`（每张图最多一个） |
| 正向变化（如 ↓跳过率、播放下降是好事） | `--teal` `#2FB3A6` |
| 中性环比（BPM 变慢、新歌率上升这类无好坏的变化） | `--muted` `#8B909A`，不加颜色 |

不再使用 `--amber` / `--blue` 之类第二强调色做图表类别——它们在 v1 的概念稿里出现，是早期版本，已删。

## 五屏的设计取舍

1. **播放器页**：不做"打开新页面"的画像——详情 / 歌词 / 画像摘要是同一个位置的三页签，切页签不该动播放条。但**画像页签只放摘要**（3 个标签 + 一句话 + 「查看完整画像 →」跳 `/music/taste`），完整画像只有独立页一处。DJ 卡放在队列上方，因为 DJ 的输出就是队列，两者必须挨着。底栏放音量条 + 静音 + 音质档（128/192/320），详情页签里也能切音质。
2. **画像页**：先给"一句话人话总结 + 五个标签"，再给图表。用户点进画像第一眼想知道"我是个什么听歌的人"，不是先看环形图。图表只留三类（语言 / 年代 / 节奏），因为这三类能从网易云 wiki 的 `genres/tags/language/bpm` 直接算出来，不需要额外埋点。
3. **周报页**：四个数字卡先行（时长 / 曲目 / 新歌 / 跳过率，都带环比，"比上一周期（前 4 周）"而不是"比上季"），中部"本周最爱 TOP（按播放次数取 7 行）+ 单曲循环"，底部一段人话总结 + 每日柱状。文案由 LLM 写，但**数字必须由代码算**，模型只负责把数字说成人话——这样周报不会因为模型幻觉变成瞎编。日柱只在峰值用红，其余灰。
4. **场景歌单**：草稿列表每首都挂入选理由（`你红心过陈粒` / `BPM 78` / `相似于《秦皇岛》`）——用户要能判断"为什么给我这首"。右侧拆成"来源统计 + 落库"两张卡，写接口未验证时主按钮置灰并写明原因。顶部三个动作语义不许混：`试听全部` = 草稿转临时播放队列（不落盘、不进历史）、`重排` = 按 BPM/情绪过渡纯代码重排（不换歌、秒回）、`换一批` = 同 brief 重新生成草稿（不覆盖上一批）。
5. **歌词二创**：左原词（带时间轴、可选中若干行）右二创（流式、可重生成）。底部固定一行"只把歌词文本发给模型 · 不发送账号信息与 cookie"——这类边界要写在界面上，不是藏在文档里。成果按钮是 `存到本机笔记`（不是"存到歌曲详情"）：只写本机笔记文件，永不写账号的详情/红心/歌单。

**响应式**：五屏都带 `@media (max-width:1120px)` 断点——宽屏是"主区 + 右栏/双栏"，窄屏一律单列（面板的队列下移到歌词下方、图表卡纵向堆叠），不出现横向滚动。截图仍在 1600 宽下取，窄屏只做验收（见 `PLAN.md` A10）。

五屏共用一套设计系统，落地时直接映射成 CSS 变量；`lib/ui/*.html` 就照这五个文件改。
